# Визуал Lancible: где что лежит

Карта того, где у каждой поверхности живут цвета, шрифты, общие детали и
стили экранов, и правила, по которым туда добавляют новое. Первая половина —
как устроено сейчас (замеры на 6 октября 2026 года), вторая — куда переезжаем
и что из этого уже сторожат тесты.

**graphify стилей не видит.** Он разбирает JS, а CSS для него — пустое место:
на вопрос «где описан переключатель» граф не ответит. По стилям навигация —
эта карта, а держит её в силе `tests/unit/visual-rules.test.js`.

## Три источника — по решению от 6 октября

У каждой поверхности свой единственный источник токенов. Значения между
поверхностями вправе различаться: десктоп с вебом, телефон и лендинг — три
отдельных набора. Внутри поверхности — один набор, и всё берётся из него.

| Поверхность | Токены | Шрифты | Стили |
|---|---|---|---|
| Десктоп и веб | `src/renderer/styles.css`, раздел «Палитра»: 78 токенов, тёмная тема по умолчанию, светлая — двумя блоками (по системе и по выбору) | Gravity и Basique Pro, `vendor/fonts/` | тот же файл; в `web/` попадает копией на сборке |
| Телефон | `mobile/src/theme.js`: `colors` / `useColors`, `spacing`, `radius`, `fontSize`, `typography`, `fontFamily` | Gravity, запасной — системный | `StyleSheet.create` в каждом компоненте и экране |
| Лендинг | сейчас — `:root` внутри каждой страницы (18 токенов); цель — `landing/landing.css` | Unbounded, Sora, JetBrains Mono — Google Fonts | сейчас — `<style>` в каждой странице; цель — общее в `landing.css` |

Почему так, а не один набор на всё: приложение и телефон — рабочие
инструменты, лендинг — витрина, и делать их одинаковыми никто не просил.
Одинаковым остаётся акцент `#87ff65` — он и есть бренд.

## Десктоп и веб: `styles.css`

### Слои — целевой порядок

Файл один, и это осознанно: его копирует сборка, читают тесты, подключают оба
`index.html`. Порядок внутри — слоями, от общего к частному. Каждый слой
открывается строкой вида `/* ========== Слой: Компоненты ========== */` —
по ней его находит тест.

1. **Шрифты** — `@font-face`.
2. **Палитра** — токены. Цвет, которого нет в палитре, сначала заводится
   здесь, в обеих темах, и только потом используется.
3. **Основа** — сброс, `body`, полосы прокрутки, иконки, анимации.
4. **Компоненты** — то, что стоит на двух и более экранах: кнопки,
   переключатель, поля, меню, модалки, тост, теги, пустое состояние.
5. **Каркас** — строка заголовка, нав-рейл, основная область.
6. **Экраны** — по разделу на экран: главная, проект, задача, календарь,
   статистика, настройки.

Экран вправе подправить компонент, но только селектором со своим классом:
`.settings-page .switch`, а не `.switch`. Иначе правка одного экрана молча
меняет все остальные, а найти её можно только по счастливой случайности.

### Как сейчас

Слоёв 1–3 и 5–6 по сути порядок держится. Слоя компонентов нет: общие детали
описаны в разделе того экрана, где впервые понадобились.

| Деталь | Классы | Где описана сейчас |
|---|---|---|
| Кнопки | `.primary` | Меню / модалки |
| | `.ghost` | Деталь задачи, Повторение задач |
| | `.danger` | Деталь задачи, Меню / модалки |
| | `.icon-btn` | Sidebar проекта, Настройка статусов, Задача с календаря, Календарь-расписание |
| | `.dp-btn` (кнопка даты) | шесть разделов |
| Переключатель | `.switch` | Полный календарь — хотя стоит в настройках и в повторении задач |
| Пустое состояние | `.empty` | Мини-календарь, Полный календарь |
| Модалки | `.modal`, `.modal-buttons` | Меню / модалки, Страница настроек, Повторение задач |
| Меню | `.ctx-menu` | Меню / модалки — на месте |
| Тост | `.toast` | свой раздел — на месте |
| Теги | `.tag…` | свой раздел — на месте |

Ещё 41 правило оформляет голые `button`, `input` и `textarea` в десяти
разделах. При переезде их надо разобрать: что из этого основа (как выглядит
любая кнопка), а что — экран.

### Цвета мимо палитры

Десять мест. Ни одно не обязано быть исключением:

- `#fff` поверх `--danger` и на бегунке переключателя — четыре места.
  Просится токен «текст на опасном».
- `#10141a` поверх акцента — четыре места. При этом в палитре уже есть
  `--accent-text` со значением `#16220e`: текст на акценте сейчас двух разных
  цветов, на глаз почти неразличимых.
- `#232428` — фон кода в редакторе.
- `rgba(0, 0, 0, 0.45)` — затемнение под модалкой.

### Стили из `app.js`

64 места, и почти все законные:

- переменные с данными пользователя — цвет проекта `--pc`, цвет статуса
  `--sc`, геометрия дорожек и сетки (`--lane-*`, `--ag-*`) — 28 мест;
- координаты и размеры всплывающих меню (`top`, `left`, `width`, `height`) —
  25 мест;
- задержка появления строк и перезапуск анимации тоста — 5 мест;
- фон из цвета, выбранного пользователем (проект, тег) — 5 мест.

Одно место — раскладка строкой (`cssText = 'display:flex;…'`): ей место в
классе.

## Телефон: `mobile/src/`

Токены собраны в `theme.js`, и система там уже полная: цвета обеих тем,
отступы, радиусы, размеры шрифта, типографика. Тему берут 54 файла из 79
(остальные — логика без отрисовки). Общие детали — `components/`, экраны —
`screens/`, навигация — `navigation/`.

Цвета мимо темы — 18 мест в 11 файлах:

- **законные**: цвета логотипа Google на кнопке входа (`AuthSheet`), красный
  экран-сигнал в редакторе, если Quill не загрузился (`RichTextEditor`),
  чёрная тень панели вкладок (`MainTabBar`), подложка тега, посчитанная из его
  цвета (`lib/tags.js`);
- **просятся в тему**: белый текст на кнопках и значках (`#fff` — четыре
  места), затемнение под шторкой, красная подложка просроченного срока —
  одна и та же в двух файлах;
- **ловушка**: у `Icon` цвет по умолчанию `#ecedef` — почти белый, и тема его
  не меняет. Сейчас все 79 вызовов передают цвет сами, но первая иконка без
  цвета окажется белой на белом в светлой теме.

## Лендинг: `landing/`

Пять страниц, у каждой свой `<style>`: правил, общих для всех пяти, — 33, для
двух–четырёх — 95, своих у одной страницы — 158 (из них 101 у главной).
Токены одни и те же, но у трёх страниц есть `--danger` и `--warn`, а у двух
нет. Шапка и подвал совпадают только потому, что их сверяют тесты.

Цель — `landing/landing.css`: токены (все 18), основа, шапка, подвал и блоки,
которые встречаются на двух страницах и больше. В `<style>` страницы остаётся
только своё. Ссылка на Google Fonts остаётся в `<head>` каждой страницы:
`@import` из CSS грузил бы шрифты на шаг позже.

## Правила

1. **Цвет — только токеном своей поверхности.** Нужного токена нет — сначала
   он заводится в источнике (в обеих темах), потом используется. Законные
   исключения перечислены в тесте поимённо и с причиной.
2. **Общая деталь живёт в общем месте**: слой «Компоненты» в `styles.css`,
   `mobile/src/components/`, `landing/landing.css`. Экран подправляет её
   только селектором со своим классом.
3. **Из JS — только координаты, размеры и данные пользователя** (цвет
   проекта, тега, статуса). Цвета палитры и раскладка — в CSS.
4. Уже закреплено раньше и остаётся: системных `<select>` нет, выпадающие
   списки — `.ctx-menu`; модалки центруются одним правилом; шапка и подвал
   лендинга одни на всех страницах.

## Что сторожит тест

`tests/unit/visual-rules.test.js`. Нынешние отступления от правил записаны в
нём списком, и список работает как храповик: новое отступление — тест
красный; отступление исправлено, а из списка не вычеркнуто — тоже красный,
чтобы список не врал. То, что зависит от переезда (слой компонентов, общий
`landing.css`), помечено `{ todo }`: видно в отчёте, сборку не красит.

Числа в этой таблице сверяет тот же тест: вычеркнули отступление из списка —
