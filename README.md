# Lancible

Настольное приложение (Electron) для ведения задач, учёта времени и заработка.

> Раньше называлось «Task Timer». Папка проекта осталась `task-timer/`, но
> приложение, exe и данные теперь `Lancible`. Данные из `%APPDATA%\task-timer\`
> переносятся автоматически при первом запуске.

## Оформление

- **Тёмная и светлая темы** + системная (следует за `prefers-color-scheme` ОС).
  Переключатель — три icon-таба (монитор/солнце/луна) внизу левого рейла
  (`.theme-tabs`, клик сразу выбирает тему, а не циклит), сохраняется в
  `settings.theme`. Палитра — CSS-переменные (`--bg`, `--panel`, `--accent`, …)
  в `src/renderer/styles.css`; тёмная (по умолчанию): `#2A2B2E` фон ·
  `#5A5A66` границы · `#87FF65` основной акцент · `#ACEB98` активный таймер/
  hover акцентных кнопок. Светлая палитра: `#F6F7F3` фон · `#EEF1EA` вторичные
  панели, чисто белые (`--panel: #ffffff`) карточки там, где раньше был
  приглушённо-серый `--panel-2` (например «Недавние задачи», `.rtile`), чтобы
  не выглядеть грязно. **Акцент на светлой теме — тот же неоновый зелёный, что
  и на тёмной, лишь чуть притемнённый** (`#7AE65B`, hover `#68C44D`) — по явному
  требованию пользователя визуально совпадать с тёмной темой важнее WCAG-
  идеального контраста как текста на белом (для заливок кнопок это не проблема:
  `--accent-text` на светлой теме тоже стал тёмным `#16220E`, как на тёмной, а
  не белым, иначе подпись на ярко-зелёной кнопке была бы нечитаемой). Ссылки в
  редакторе — отдельный токен `--link` (голубой, `#5EC8F2` тёмная / `#1C72B0`
  светлая), не завязан на акцент.
- Нативные кнопки окна (свернуть/развернуть/закрыть, рисуются Windows поверх
  страницы через `titleBarOverlay`) **синхронизируются с темой из рендерера**:
  `applyTheme()` шлёт `window.api.setTitlebarOverlay(theme)` → IPC
  `theme:set-overlay` в `src/main.js`, который резолвит `'system'` через
  `nativeTheme.shouldUseDarkColors` и красит кнопки в `--bg`/`--text-dim`
  подходящей темы; при старте окна цвет уже выставляется правильно (тема
  читается из `data.json` синхронно, до создания `BrowserWindow`). ОС
  переключилась между светлой/тёмной, пока приложение открыто в режиме
  «Системная» — переслушивается через `matchMedia('(prefers-color-scheme: dark)')`.
- Скроллбар везде в приложении — тонкий и минималистичный, без стрелок
  (`::-webkit-scrollbar-button{display:none}`) и со скруглённым бегунком, цвет
  в тон темы (`--border-strong`, темнее при наведении). Только
  `::-webkit-scrollbar*` — **без** `scrollbar-width`/`scrollbar-color`: в
  Chromium если на элементе заданы обе группы свойств одновременно, побеждают
  стандартные и весь webkit-кастом молча игнорируется (скроллбар откатывается
  на вид по умолчанию — широкий, со стрелками), хотя приложение — Electron/
  Chromium-only, кроссбраузерный fallback тут не нужен.
- Шрифт **Basique Pro** (woff2, веса 300/400/700/900). Исходники — в папке
  `font/` (её кладёт пользователь); `scripts/copy-vendor.js` копирует нужные
  начертания в `src/renderer/vendor/fonts/` на `postinstall`. Если `font/` нет —
  интерфейс откатывается на системный шрифт.
- Стандартное меню Electron (File/Edit/View/…) убрано
  (`Menu.setApplicationMenu(null)`); вместо него своя строка заголовка
  `#titlebar` с логотипом-акцентом и кнопками окна через `titleBarOverlay`.
  В dev-режиме F12 — DevTools, Ctrl+R — перезагрузка.
- Токены — CSS-переменные в начале `src/renderer/styles.css`.
- Логотип и иконка приложения — фирменный знак (ракета) акцентного цвета
  `#87ff65` на графитовом скруглённом квадрате; исходник — `build/logo-accent.svg`,
  тот же путь вписан inline в `.tb-logo-mark` (`fill="currentColor"`) в шапке.
- **Интерфейс на 4 языках** — русский, English, українська, қазақша (кнопка
  рядом с темой в рейле открывает свой попап-список — не нативный `<select>` —
  с галочкой у текущего языка, через переиспользуемое плавающее меню
  `openMenu()`/`#ctx-menu`; сохраняется в `settings.lang`). Перевод — таблица `T` в
  начале `src/renderer/app.js` + `t('ключ', {подстановки})`; статичная разметка
  размечена атрибутами `data-i18n`/`data-i18n-ph`/`data-i18n-title`/`data-i18n-aria`
  и применяется через `applyStaticTranslations()`. Множественное число — по
  языковым правилам (`pluralForm`, слав. 1/2-4/5+ для ru/uk, en — sing/plur,
  kk — без словоизменения). Даты/числа — через `Intl`/`toLocaleDateString` с
  локалью текущего языка (`LOCALE_MAP`). Собственные данные пользователя
  (названия проектов/задач, тексты заметок) не переводятся — язык влияет только
  на интерфейс.

## Что умеет

### Навигация
- **Шапка окна** (`#titlebar`, как в Kaspersky Premium): логотип + название слева
  (размер логотипа не меняется — только позиция), рядом широкая строка **поиска**;
  результаты выпадают прямо под ней. Правее — системные кнопки окна
  (`titleBarOverlay`).
- **Левый рейл** (`#navrail`): разделы **Обзор / Календарь**, кнопка **Свернуть**
  (рейл плавно сжимается до иконок вместе с логотипом в шапке — анимация через
  `transition: width`/`margin-left` на элементах, вынесенных из flex-потока в
  `position: absolute`; состояние — в `ui.navCollapsed`).
- **Поиск** (клик/фокус на строке в шапке или `Ctrl+F`): по проектам и задачам,
  результаты отдельными группами (название на отдельной строке над подписью —
  проектом/статусом); у задачи показано, к какому проекту она относится;
  ↑↓/Enter для выбора; клик вне панели или Esc закрывают её.
- **Верхняя панель статистики** (`#topbar`) — **только на «Обзоре»**: 4 крупные
  карточки (всего проработано, всего заработано, **заработано в этом месяце** —
  от начала до конца текущего месяца, задач выполнено) + чип работающего таймера.
- Иконки — монохромные с заливкой (SVG, цвет `--icon`), не эмодзи.

### Обзор (`#home-view`)
- `#home-view` сам — сетка на 2 колонки (`grid-template-columns: 1fr 300px`)
  во всю высоту вида: слева `.home-center` (скроллящийся контент + прибитые
  снизу «Недавние задачи»), справа `#home-side` — календарная панель тянется
  **от самого верха до самого низа окна**, а не только на высоту левой сетки.
  Статистика (`#topbar`) лежит **внутри** `.home-main`, поэтому её правый край
  упирается ровно в границу календарной панели; линия-разделитель под
  статистикой убрана (только отступ). Заголовок секции «Проекты · N» и кнопка
  «Создать проект» (`.home-head`) — `flex-wrap`, кнопка переносится под
  заголовок на узком окне вместо наползания на текст.
- Плитки проектов: цветная полоса слева, название, описание, время, деньги,
  задачи, прогресс, дата. «⋮» при наведении: открыть · редактировать ·
  закрепить · скачать Excel · скопировать сводку · удалить. Плитка **`+`**
  полного размера. **Закреплённые** — в одну строку с горизонтальной
  прокруткой (`.car-track`, padding подобран так, чтобы hover-тень плитки не
  обрезалась краем скролл-контейнера). **Остальные** — плитки идут слева
  направо и **переносятся на новую строку** (`.projects-grid`, обычный
  `flex-wrap`; сами плитки в этой сетке могут сжиматься `flex:0 1 250px` —
  иначе на узком окне фикс-ширина 250px тянула за собой нежеланный
  горизонтальный скролл всей главной), без горизонтального скролла; при
  нехватке места вся левая колонка скроллится вертикально. Стрелки карусели
  (в обеих группах) не дизейблятся с тусклой иконкой, а **полностью
  скрываются**, когда скроллить в эту сторону некуда, и появляются по мере
  прокрутки.
- **Недавние задачи** — отдельная полоса, **всегда прибитая к низу экрана**
  (`#recent-section.recent-fixed`, вне зоны прокрутки `.home-grid`, с той же
  заливкой фона и линией-разделителем сверху); ряд маленьких плиток (белый
  фон `--panel`, а не приглушённый `--panel-2`, чтобы не выглядеть тускло —
  чекбокс, название, проект, время), прокручивается горизонтально.
  Выполненные задачи в этот список не попадают.
- Справа — **мини-календарь** месяца во всю высоту вида, итог за месяц, и внизу
  две карточки — **«Сегодня»** и **«За неделю»** (время + деньги за текущую
  календарную неделю).

### Календарь (`#calendar-view`)
- Режимы **Месяц / Неделя / День** — переключатель и заголовок периода
  («‹ Сентябрь 2026 ›») центрированы между стрелками навигации; сама группа
  стрелки+заголовок+«Сегодня» обёрнута в `.cal-nav`, чтобы на узком окне она
  переносилась как единый блок, а не рассыпалась по одной кнопке на строку;
  правая панель календаря — `minmax(220px, 340px)` (не жёсткие 340px), чтобы
  левой колонке оставалось больше места на минимальной ширине окна. В **Дне** —
  почасовая раскладка на 24 строки: часы без записей приглушены, часы с
  сессиями показывают чипы задач (цвет — проекта); клик по чипу открывает
  задачу. Строка часа не сжимается флексом ниже своего реального содержимого
  (`flex-shrink: 0` — раньше при большом количестве чипов в одном часе флекс
  ужимал `.hour-row` до min-height и чипы визуально вылезали за её границы);
  сами чипы при этом остаются сжимаемыми и переносят длинный текст по словам,
  а не растягивают всю раскладку по горизонтали.
- **Правая панель всегда показывает итог за месяц/неделю** (в режиме «День» не
  нужен — там и так есть итог по дню) серым блоком **«За месяц: Xч · Y ₽»**
  сверху (нейтральная заливка `--panel-2`/`--border`, без акцентного тона —
  раньше был зеленоватый `color-mix` с акцентом) — независимо от того, включён
  ли ниже режим периода.
- Переключатель **«Выбрать период»** — работает поверх любого режима (месяц/
  неделя/день, плавно проявляется при включении): показывает две кнопки даты
  «от»/«до» (по умолчанию — границы текущего вида) и **подсвечивает диапазон на
  сетке анимированной вспышкой** зелёного (2 клика по дням — начало и конец).
  Ниже итога за месяц/неделю — не список сессий одного дня, а **сводка по
  задачам за весь период** (сколько всего заработано и потрачено времени на
  каждую, с иконкой готовности) и зелёный бейдж **«За период: Xч · Y ₽»**.
- Кнопки «от»/«до» открывают **свой попап-календарь** (не системный пикер ОС) —
  вся кнопка кликабельна, вид под стиль приложения; клик по дню сразу
  применяет дату и закрывает попап. Тот же попап переиспользуется и в диалоге
  «Добавить запись» (см. ниже) — единая реализация `openDatePicker(anchor,
  value, onPick)` под оба места.
- Без периода: клик по дню → правая панель с разбивкой по сессиям (время,
  задача+проект, длительность, сумма). Клик по сессии открывает задачу.
- Ставка зафиксирована на момент записи (`session.rate`) — смена ставки не
  переписывает историю.

### Проект
- По клику на плитку; в шапке «‹ Все проекты», цветная точка, название, «⋮».

### Задачи
- Список с чекбоксами; **пины** (📌 у задачи и у заголовка) поднимают задачу
  наверх под разделителем; выполненные уходят в отдельный блок **«Выполненные»**
  внизу списка (группы показываются, только если в них правда что-то есть).
- **Фильтр** над списком: статус **Все / В работе / Готово** — при активном
  фильтре список плоский (без «Закреплённые»/«Выполненные»), но пин у задачи
  остаётся кликабельным. «Закреплённые» как значение фильтра намеренно не
  предусмотрены — это группировка, а не статус (фильтра по дате создания нет —
  убрали как непрактичный).
- Заголовок задачи: название, пин, **удаление** — просто иконка мусорки (без
  текста), с подтверждением через **свой диалог** (не системный `confirm()`),
  стилизованный под приложение, — и правее всех, у самого края, переключатель
  вкладок **«Заметки» / «История»**. Строка заголовка — `flex-wrap`, а поле
  названия держит `min-width: 140px`: на узком окне вкладки переносятся на
  свою строку, но название задачи никогда не сжимается до нечитаемой ширины
  (было — пропадало полностью на минимальной ширине окна).
  - **«Заметки»**: таймер (кнопка **Старт/Стоп у правого края** блока — слева
    только дисплей времени), ставка/калькулятор заработка и редактор.
  - **«История»**: записи времени крупными карточками (больше места, чем раньше
    в узкой раскрывашке, с заметным отступом от вкладок сверху), кнопки
    **«+ Добавить запись»** (акцентная, зелёная) и «⬇ Excel».
- Редактор заметок (Quill): заголовки, жирный/курсив/зачёркнутый, **цвет текста и
  фона** (палитра под цветокор), чек-листы, списки, отступы, цитаты, код, ссылки
  (`--link`, голубые — отдельный от акцента токен). Подсказка ссылки
  (URL + Edit/Remove) теперь не обрезается — контейнер редактора держит
  скруглённые углы на тулбаре/поле ввода напрямую, а не через `overflow:hidden`
  на обёртке (которая раньше срезала всплывающую подсказку) — и не вылезает за
  границы редактора: Quill сконфигурирован с `bounds: '#editor-wrap'`, так что
  сам позиционирует/переносит подсказку внутри карточки редактора, а не всей
  страницы. **«Remove»** в подсказке — красный (`--danger`), не синий.
  **Таблицы** (кнопка ▦): когда курсор в таблице — панель под редактором:
  строки/столбцы + **заливка ячейки / строки / столбца** цветом (через блочный
  атрибутор `cellBg`, попадает в Delta).
- Таймер **Старт / Стоп**, один на всё приложение.
- **Записи времени**: журнал сессий (вкладка «История») + **ручное добавление /
  правку** через диалог с **полностью кастомными полями** — дата открывает тот
  же попап-календарь, что и период в календаре; начало/конец — свой попап
  выбора времени (`#tp-pop`, два прокручиваемых столбца часы/минуты, под цвета
  приложения) вместо системных `<input type="date">`/`<input type="time">`.

### Деньги
- «Ставка по умолчанию» + **валюта из списка** (USD/EUR/RUB/KZT/UAH/… — выбор,
  не ввод) в подвале.
- Своя ставка у задачи перебивает дефолт; под таймером — `время × ставка =
  заработано` вживую.
- Итоги по проекту, по месяцу, по дню — везде в деньгах и времени.

### Выгрузка в Excel (.xlsx)
- По задаче (**⬇ Excel**) и по проекту (меню «⋮» → «Скачать Excel»): колонки
  «Часы», «Ставка», «Сумма», строки «Итого» с формулами `SUM`. Формат
  генерируется без сторонних библиотек (`src/xlsx.js`).

### Прочее
- Плавные анимации: появление видов/плиток, ховеры, нажатия (`scale(.97)`),
  модалки (`popIn`), тосты. Уважает `prefers-reduced-motion`.
- Автосохранение в JSON; таймер восстанавливается по «пульсу» (раз в 15 сек).
- Приложение всегда стартует с **Обзора**. Схема мигрирует автоматически: валюта
  символ → код (`₽`→`RUB`), проектам добавляются `color`/`description`/`pinnedAt`,
  задачам — `pinnedAt`, сессиям — `rate` (у старых берётся текущая ставка),
  в `ui` — `navCollapsed`.

## Запуск для разработки

```bash
npm install
npm start
```

`npm install` заодно копирует файлы редактора Quill в `src/renderer/vendor/`
(скрипт `scripts/copy-vendor.js`).

## Сборка .exe и автообновление

```bash
npm run build:exe
```

Это:

1. `npm run icon` — рисует `build/icon.ico` (графит + акцентное лого-ракета из
   `build/logo-accent.svg`);
2. `npm run package` — **`electron-builder`** собирает NSIS-инсталлятор
   `dist/Lancible Setup X.Y.Z.exe` (one-click, ставится в
   `%LOCALAPPDATA%\Programs\Lancible`, сам создаёт ярлыки на рабочем столе и в
   «Пуск») + `dist/latest.yml` — метаданные для автообновления.

Приложение теперь **обновляет себя само**: при запуске (только в собранном
`.exe`, не в `npm start`) `src/main.js` через `electron-updater` тихо проверяет
`dist/latest.yml`, опубликованный в Supabase Storage (см. ниже); если версия
новее — в левом рейле снизу появляется зелёная кнопка «Доступно обновление»;
клик скачивает файл, кнопка становится «Перезапустить» — второй клик тихо
ставит новую версию и перезапускает приложение. Никакого мастера/диалогов
между двумя кликами не показывается (`oneClick: true` обязателен для этого —
без него `quitAndInstall()` открывает полный мастер установки и не завершает
процесс).

**Публикация новой версии**:
1. Подними `"version"` в `package.json`.
2. `npm run build:exe`.
3. `npm run publish:release` — заливает `dist/*.exe` + `.blockmap` +
   `latest.yml` в публичный Supabase Storage bucket `releases` (нужны
   `SUPABASE_URL`/`SUPABASE_SERVICE_ROLE_KEY` в `.env`, см. комментарий в
   `scripts/publish-release.js` — файл `.env` никогда не коммитится).

> На этой машине у `npm` есть allowlist на install-скрипты зависимостей
> (`npm-lavamoat`) — после `npm install` может появиться предупреждение
> `N packages have install scripts not yet covered by allowScripts`. Чинится
> через `npm approve-scripts <имя-пакета>` (запускает нужный скрипт и
> запоминает разрешение в `package.json`) — так это и было исправлено для
> `electron` и `electron-winstaller` (нужен `electron-builder`'у для сборки
> NSIS). Так надёжнее, чем распаковывать вручную.

## Аккаунты и облачная синхронизация (в разработке)

- Бэкенд — **Supabase** (Postgres + Auth + Storage): проект
  `yiglgfkjjvwijukdzutw`, схема таблиц (`profiles`/`projects`/`tasks`/
  `sessions`/`user_settings`, все с RLS `user_id = auth.uid()`) — в
  `supabase/schema.sql`. Клиент — `@supabase/supabase-js` (UMD-сборка,
  вендорится в `src/renderer/vendor/supabase.js` тем же `copy-vendor.js`, что и
  Quill; `contextIsolation` не даёт использовать `require()` в рендерере,
  поэтому подключается как обычный `<script>`).
- **Вход опционален** — кнопка «Войти»/имя пользователя в рейле
  (`#account-btn`), не блокирует работу офлайн.
- Вход по **email + паролю**: одна форма на вход и регистрацию — если
  «неверные данные», предлагается «Нет аккаунта? Создать» тем же email+
  паролем (Supabase не даёт заранее проверить существование email — это
  защита от enumeration-атак, так делают Slack/Notion). Проект по умолчанию
  требует подтверждение email — если `signUp()` не вернул сессию сразу,
  показывается экран «проверьте почту» (`#auth-step-confirm`) вместо
  мгновенного онбординга.
- **Онбординг** (имя + «для чего используете», для аналитики) показывается не
  сразу после регистрации, а **при первом реальном входе с сессией** —
  `afterSignedIn()` проверяет, есть ли уже строка в `profiles` для этого
  `user.id`; если нет — онбординг, если есть — сразу вход. Это правильно
  обрабатывает и случай с отложенным подтверждением email.
- Google-вход (через системный браузер + кастомный протокол
  `lancible://auth-callback`) и сама синхронизация данных (`projects`/
  `tasks`/`sessions` ↔ Supabase, realtime, офлайн-очередь) — ещё не сделаны,
  следующие этапы.

## Где хранятся данные

`data.json` в папке пользовательских данных Electron:
`%APPDATA%\Lancible\data.json` (Windows). При первом запуске данные из старой
папки `%APPDATA%\task-timer\` копируются автоматически (см. `loadData()` в
`src/main.js`).

Схема:

```jsonc
{
  "projects": [{ "id", "name", "createdAt", "color": "#87ff65",
                 "description", "pinnedAt": "..." | null }],
  "tasks":    [{ "id", "projectId", "title", "done", "notes": <Quill Delta|null>,
                 "totalMs", "rate": 3000 | null, "pinnedAt": "..." | null,
                 "sessions": [{ "start", "end", "ms",
                                "rate": 3000,          // ставка на момент записи
                                "manual"|"recovered": true }] }],
  "activeTimer": { "taskId", "startedAt", "heartbeatAt" } | null,
  "ui": { "view": "home"|"project"|"calendar", "projectId", "navCollapsed": false },
  "settings": { "hourlyRate": 0, "currency": "RUB",       // код валюты
                "theme": "system"|"light"|"dark", "lang": "ru"|"en"|"uk"|"kk" }
}
```
`notes` Delta может содержать `table`-атрибуты и `cellBg` (фон ячейки таблицы).

| --- | --- |
| `src/main.js` | Главный процесс: окно (свой titlebar, без меню), `data.json` + миграция, диалог .xlsx, синхронизация цвета кнопок окна с темой (`theme:set-overlay`), автообновление через `electron-updater` (`update:check`/`update:download`/`update:install`). |
| `src/preload.js` | Мост `window.api` (`load` / `save` / `exportXlsx` / `copy` / `setTitlebarOverlay` / `checkForUpdate` / `downloadUpdate` / `installUpdate` + подписки `onUpdate*`). |
| `src/xlsx.js` | Мини-генератор .xlsx (ZIP + OOXML) без зависимостей. |
| `src/renderer/index.html` | Разметка: `#titlebar` (лого + поиск), `#navrail` (+ переключатели темы/языка), `#home-view` (статистика внутри `.home-main`, `.projects-grid`, `#recent-section.recent-fixed`), `#project/calendar-view`, вкладки задачи (`#task-tabs`/`#tab-notes`/`#tab-history`), фильтр задач в `#sidebar`, попапы кастомного календаря/времени (`#dp-pop`/`#tp-pop`, общие для периода в календаре и диалога записи времени), диалог подтверждения (`#confirm-backdrop`), `#search-panel`. Все статичные подписи размечены `data-i18n*`. Иконки — инлайн-SVG. |
| `src/renderer/styles.css` | Стили, палитра (тёмная/светлая — CSS-переменные + `[data-theme]`/`prefers-color-scheme`), анимации, `@font-face` Basique Pro. `.icon` — `--icon` цвет. |
| `src/renderer/app.js` | Логика: **i18n** (словарь `T`, `t()`, `pluralForm()`, `applyStaticTranslations()`, `LOCALE_MAP`), **темы** (`applyTheme`/`cycleTheme`), рейл (сворачивание — один класс `body.nav-collapsed`, элементы вынесены в `position:absolute` ради плавной анимации ширины), поиск из шапки, маршрутизатор видов, плитки/карусели, недавние задачи (без готовых), календарь (`aggregateDays`/`rangeAgg`, режимы month/week/day, `renderViewTotal` — итог за месяц/неделю всегда в правой панели, `calState.periodOn` + `renderPeriodSummary`), обобщённые попапы даты/времени (`openDatePicker`/`openTimePicker`, принимают anchor+value+callback — используются и календарём, и диалогом записи времени), фильтр задач по статусу (`taskFilter`, `filteredProjectTasks`), вкладки задачи (`setTaskTab`), диалог подтверждения (`confirmDialog`, замена `window.confirm`), диалоги проекта и записи времени, меню, пины, редактор (цвет текста + таблицы + `cellBg` через Parchment StyleAttributor), таймер, деньги (`sessionRate`), экспорт (заголовки тоже через `t()`), миграция. |
| `scripts/copy-vendor.js` | Копирует Quill + шрифт в `src/renderer/vendor/` (postinstall). |
| `scripts/make-icon.js` | Генерирует `build/icon.*` из `build/logo-accent.svg` (canvas + `Path2D`/`Image`, собирает `.ico` через `png-to-ico`). |
| `scripts/publish-release.js` | Заливает `dist/*.exe`/`latest.yml` в Supabase Storage (`npm run publish:release`). |
| `supabase/schema.sql` | Схема БД для аккаунтов/синхронизации (таблицы + RLS-политики), выполняется вручную в SQL Editor проекта. |
| `scripts/smoke.js` | Headless-проверка UI (`npm run smoke`); окно рендерера — на изолированной сессии (`partition: 'nopersist:smoke'`), чтобы реальная Supabase-сессия из ручных прогонов не протекала между запусками. |
| `scripts/xlsx-check.js` | Проверка генератора .xlsx (`npm run check:xlsx`). |
